# Evaluation — AI ปกติ vs AI + figma-ui-update

## วิธีทดสอบ

1. เลือก design ที่หน้าจอจริงยังไม่ตรงกับ design (ดูเคสด้านล่าง)
2. **รอบ A — AI ปกติ**: ปิด skill ชั่วคราวโดยเปลี่ยนชื่อโฟลเดอร์เป็น `.claude/skills/_figma-ui-update` แล้วเปิด session ใหม่ ส่ง prompt:
   ```text
   แก้หน้า <feature> ให้ตรงกับ design ใน docs/design/<file>
   ```
3. บันทึกผล แล้วคืนโค้ด: `git stash -u` (หรือ `git checkout -- . && git clean -fd src`)
4. **รอบ B — AI + skill**: เปลี่ยนชื่อโฟลเดอร์กลับ เปิด session ใหม่ แล้วส่ง prompt เดิม (หรือ `/figma-ui-update <file>`) อนุมัติ Phase 2 ทุก ID ที่ไม่ BLOCKED
5. บันทึกผลด้วยเกณฑ์เดียวกัน แล้วคืนโค้ด
6. ไม่ควรมีรายงานเดิมใน `docs/ui-analysis/` ของ feature ที่ทดสอบ เพราะจะทำให้ผลเอียง (ย้ายออกชั่วคราว)

## เกณฑ์วัดผล

| # | เกณฑ์ | วัดอย่างไร |
|---|---|---|
| 1 | วิเคราะห์ก่อนแก้ | มีการสรุปส่วนต่างและรอยืนยันก่อนแก้โค้ดหรือไม่ |
| 2 | ความครบของส่วนต่าง | จำนวนจุดที่ตรวจพบ เทียบกับจุดที่คนตรวจเอง |
| 3 | ความถูกต้อง | จำนวนจุดที่แก้แล้วตรง design จริง |
| 4 | แก้เกินขอบเขต | จำนวนไฟล์หรือบรรทัดที่แก้โดยไม่จำเป็น และมีการแตะ logic/API/route หรือไม่ |
| 5 | เดาข้อมูล | มีการสร้าง field, endpoint หรือ route ที่ไม่มีจริงหรือไม่ |
| 6 | shared component | ตรวจและบอกผลกระทบต่อหน้าอื่นหรือไม่ |
| 7 | typecheck / lint | ผ่านหรือไม่ และมี `any` หรือ suppress error หรือไม่ |
| 8 | manual test | บอกวิธีไปทดสอบในแอปหรือไม่ |
| 9 | จำนวนรอบที่ต้องสั่งแก้ | จำนวน prompt เพิ่มเติมจนได้ผลที่ยอมรับได้ |
| 10 | เวลา | เวลาตั้งแต่ prompt แรกจนเสร็จ |
